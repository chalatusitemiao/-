# 车队管理系统 · 车辆 / 司机 / 路线 / 油耗考核

纯前端的车队管理演示系统。**Vue 3 + Vite，没有后端、没有数据库、没有 UI 组件库** ——
读 Excel 的解析器也是自己写的，依赖只有 `vue` + `vite`。

当前启用了六个模块：**车辆管理、司机管理、路线管理、趟次管理、收入、成本**。
桌面端是左侧边栏、移动端是底部标签栏，
往 `router.js` 的 `TABS` 里追加一项就多一个模块，菜单会自动出现。

概览看板 / 报表 / 成本这三个模块已移到 `src/_archived/`，
等做到那一步再搬回来（见文末「归档说明」）。

视觉风格是**现代轻卡片风**：浅灰底 + 纯白卡片 + 大圆角 + 低透明度分层阴影 + 单一强调色（靛蓝 `#4f46e5`）。
字体走系统原生（iOS/macOS 是 SF Pro，Windows 是 Segoe UI Variable，中文落苹方/鸿蒙/雅黑），不联网加载字体。
数字统一 `tabular-nums`，列表刷新时不会左右跳动。

```bash
npm install
npm run dev          # 打开 http://localhost:5180
```

（形如 `http://192.168.x.x:5180`）。建议「添加到主屏幕」，全屏后刘海屏手势条区域会被正确避让。

## 车辆模块

### 可录入的字段（6 项）

| 字段 | 校验 |
| --- | --- |
| 车牌号 | 必填 |
| 车类型 | 必填；牵引车 / 厢式货车 / 冷藏车 / 平板车 / 自卸车 |
| 载重 | 必填；> 0 且 ≤ 100 吨；超出该车型常见区间时给**软提示**但不阻塞提交 |
| 购置价格 | 必填；> 0；实时回显「≈ 44.5 万元」 |
| 购置日期 | 必填；不能晚于今天；车龄超过 12 年给**软提示**；用于计提折旧 |
| 当前累计里程 | 必填；≥ 0；用于推算下次保养提醒 |

### 关于车编号

车编号在数据模型里仍然保留（新增时按 `V01`、`V02`… 自动分配，是这台车的稳定标识），
但**前台完全不显示**：列表里没有这一列，表单里没有这个输入框，导入模板里也没有这一列，
文案里也不再提它。

原因是它对用户没有意义 —— 系统自己生成的编号，摆在界面上既不能改、也不解决任何问题，
反而会让人以为需要自己维护。以后真接了后端、由对方下发车编号时，这个字段一直都在。

### 自动补齐的字段

表单只收 6 项，其余按车型推导出合理默认值：百公里油耗基准、油箱容量、保养间隔、状态、燃料类型。
所以录入的车是一条**完整记录**，能直接参与后续的成本分析，而不是缺胳膊少腿。
换车类型时油耗基准与油箱容量会跟着换，不会出现「厢式货车套用牵引车油耗」。

### 列表

桌面端（≥ 760px）是表格，表头可点排序（载重 / 购置价格 / 购置日期 / 累计里程）；
移动端（< 760px）是卡片列表 —— **两套 DOM 各自排版**，不是把表格硬压成卡片，
所以手机上既没有横向滚动、也不会挤成一团。

**搜索只按车牌号和车类型**（不搜车编号、不搜车型）。另外有车型筛选胶囊。

列表默认**按车型分组**：相同车型的车归到一组，组头给出「N 台 · 合计载重 · 月折旧」——
同类型车放一起才好横向比，也不至于在长列表里翻来翻去。
想按全表排序（载重 / 价格 / 购置日期 / 里程）时可以切到「不分组」，
分组时排序在组内生效。移动端同样按车型分块显示。

数据存在 `sessionStorage`（键 `fleet.vehicles.v4`）：**刷新不丢，关闭标签页后自动清空**。
刻意不用 `localStorage` —— 调试期间不希望上一次的数据一直粘在那里。

### 删除

**每台车都有独立的删除按钮**（桌面在操作列、移动端在卡片底部），
点下去会弹一个**二次确认框**，写清楚要删哪台车、购置价格和累计里程是多少，确认后才真的删。

确认框是自绘弹层（`ConfirmDialog.vue`）而不是 `window.confirm`：原生弹窗样式不可控、
会阻塞主线程，移动端浏览器里标题还会显示成域名，很出戏。

界面上**没有「清空全部」**这种批量操作 —— 删除只按台进行，避免误操作清库。
（`store/vehicles.js` 里留了一个 `clearAll()`，只给自检脚本重置状态用，界面上没有入口。）

## 折旧

按**5 年直线法、残值 10%**计提：

```
月折旧   = 购置价格 × (1 - 10%) ÷ 5 年 ÷ 12 个月
当前净值 = max(残值, 购置价格 - 月折旧 × 已使用月数)
```

提满 5 年后净值停在残值上，不再继续计提（列表里会标「已提足」）。

**在哪能看到**：

- **录入表单**：填完购置价格与购置日期，立刻显示月折旧 / 已使用年数 / 当前净值
- **列表**：购置日期下方跟一行「车龄 X 年」，移动端卡片还有一栏「月折旧」
- **汇总条**：「月折旧合计」直接给整个车队每月的折旧支出（以及年折旧），
  车队有已提足的车时，「平均车龄」那张卡会补一行「已提足折旧 N 台」

> Excel 里的日期单元格存的是**序列号数字**（如 44638），不是文本。
> 解析器会把数字按 Excel 序列号还原（含 1900 闰年 bug 的处理），
> 所以文件里既可以用真日期格式，也可以写 `2022-03-18` 这样的文本。

## Excel 批量导入

点「批量导入」→ 选文件（支持 `.xlsx` 和 `.csv`，也可以直接拖进去）。

### 规则：车牌号就是主键

- 文件里的车牌号**已存在** → **替换**原来那台车的资料（保留原 id 与车编号）
- 文件里的车牌号**不存在** → **新增**一台

所以**没有列映射，也没有「跳过 / 覆盖」的选项** —— 读进来直接给结果。
表头按别名自动识别（「载重（吨）」「核定载重」「吨位」「购买日期」都能对上），列顺序随意。
万一有必填列没认出来，会直接告诉你缺哪几列，让你对照模板改表头，而不是让你手动映射。

### 流程仍然分两步

**先读进来给人看，再确认写进去。** 导入最容易出事的不是解析，而是脏数据静默进库，
所以逐行过一遍**和表单完全相同的校验规则**（`utils/vehicleRules.js` 一份定义，两处使用），
把结果分成三类：

| 结果 | 含义 |
| --- | --- |
| **新增** | 数据合法、车牌在系统里不存在 |
| **替换** | 数据合法、车牌已存在，会覆盖那台车 |
| **错误** | 数据有问题，**不能导入**（能看到是哪个字段、错在哪） |

只有当错误行被排除后仍有可导入的行，提交按钮才可用。

### 脏数据的处理

| 原始值 | 处理结果 |
| --- | --- |
| `¥418,000 元` | `418000` |
| `32 吨` | `32` |
| `386,000 km` | `386000` |
| `苏e8k215` | `苏E·8K215` |
| `半挂` / `厢式` / `冷链` / `泥头` | `牵引车` / `厢式货车` / `冷藏车` / `自卸车` |
| `44638`（Excel 日期序列号） | `2022-03-18` |
| `2022/3/18`、`2022年3月18日`、`20220318` | `2022-03-18` |
| `2023-02-30`（不存在的日期） | 判错，不会自动进位成 3 月 2 日 |
| 空行 | 跳过 |
| 文件里两行同一个车牌 | 判错，并指出「前面的行已经用过」 |
| 已经存在但写法不同的车牌 | 判为重复（车牌读进来时就已归一化） |
| 购置日期在未来 | 判错 |

### 模板

「下载导入模板（CSV）」按钮在前端直接生成带 BOM 的 CSV，Excel 双击打开不乱码。
表头就是上面那 6 个字段。

### 已知限制

- **只读第一张工作表**。数据在第二张表上就读不到（已在自检里显式断言这个行为，避免以后误以为支持）
- **不支持旧版 `.xls`**（那是 OLE 复合文档，不是 ZIP）。上传时会给出明确提示，让你另存为 `.xlsx` 或 `.csv`
- 不支持合并单元格
- 没有做「导入预览里直接改单元格」，有问题请改源文件后重传

## 司机模块

司机模块的结构比车辆多一层，字段按需求分成**三类**，这个分类直接写进了代码
（`utils/driverRules.js` 里 `UPLOAD_FIELDS` / `STAT_FIELDS` / `INCIDENT_FIELDS` 三个数组）：

### 一、可上传字段（表单能填、Excel 能导）

| 字段 | 校验 |
| --- | --- |
| 姓名 | 必填；**不做字数与字符集限制**（单字名、带数字或连字符的名字都放行） |
| 手机号 | 必填；**唯一**；**不做格式校验**。归一化只去首尾空格、压缩内部空格 —— 横线、括号都原样保留 |
| 入职日期 | 必填；不能晚于今天；工龄超过 15 年给**软提示** |
| 驾驶证号 | **选填**；**不做长度与字符集限制**；填了只查「有没有和别人的重复」 |
| 工资 | **选填**，元/月；填了要是合理数字（`8,800 元`、`¥12000` 都能清出来），0 会给软提示。用于统计人工成本 |

### 二、自动统计字段（表单不能填、Excel 不能导）

| 字段 | 说明 |
| --- | --- |
| 当月创收 | 由运营流水按司机按月汇总 |
| 当月总里程 | 同上 |
| 当月总油耗/电耗 | 燃油车按升（L）、电动车按千瓦时（kWh）；同类相加，油电混合会显示成 `1,200 L + 90 kWh` |

**这三个字段由「趟次记录」自动汇总**（见下文「油耗考核」）：

```
司机当月创收   = Σ 该司机当月趟次的运费收入
司机当月总里程 = Σ 该司机当月趟次的公里数
司机当月总油耗 = Σ 该司机当月趟次的实际油耗
```

一个月的趟次还没录时显示「—」而不是 0 —— 这样「真的跑了 0 公里」和「这个月还没录数据」
不会被混为一谈（`aggregateOps` 没有数据时返回 `null`）。
自检里跑了完整闭环：录两位司机的趟次 → 渲染司机页 → 断言金额 / 里程 / 油耗真的出现在列表上。

汇总函数没有数据时返回 `null` 而不是 `0` —— 这样「真的跑了 0 公里」和「还没接入数据」
不会被混为一谈，界面据此显示「—」。

### 三、事故 / 违章记录（手工添加，不可导入）

每位司机名下可以挂多条记录，每条三个字段：

| 字段 | 校验 |
| --- | --- |
| 发生时间 | 必填；不能晚于今天 |
| 事件描述 | 必填；2~200 字 |
| 经济损失 | 必填；≥ 0（没有损失填 0） |

入口在**司机编辑弹窗里的子列表**：打开某位司机就能看到他的记录，下面有「添加一条记录」，
每条可以单独删除，右上角实时显示「N 条 · 共 ¥X」。
这一整份列表跟着主表单的「保存修改」一起提交 —— 只有一个保存动作，取消不会影响原数据。
新增司机时看不到这个区域（还没有 id 可挂），会提示「先保存司机，之后再添加」。

列表上每位司机显示一个红色胶囊「2 次 · ¥8,800」，没有记录的显示「无」。
汇总卡里也有一个「事故 / 违章」总数与累计经济损失。

### 导入

和车辆模块完全一致的规则：**手机号就是主键**。

- 文件里的手机号**已存在** → **替换**那位司机的资料（保留原 id 与已有的事故记录）
- 文件里的手机号**不存在** → **新增**一位

没有列映射、没有「跳过 / 覆盖」选项。表头按别名识别（「司机姓名」「联系电话」「入职时间」「驾照号」都能对上）。
模板只有那四列 —— 统计字段与事故记录本来就不该出现在导入文件里，这条也有断言守着。

### 列表

桌面端 9 列（姓名 / 手机号 / 入职日期+工龄 / 驾驶证号 / 当月创收 / 当月里程 / 当月油耗电耗 / 事故违章 / 操作），
三个统计列的表头带一个「自动」小角标，提示它们不是人工填的。
移动端是卡片列表（含工龄与经济损失）。

**搜索只按姓名和手机号**。数据同样存在 `sessionStorage`，默认空列表。

## 车型基准表与油耗模型

### 车型是自由输入的，基准表只用来算油耗

车辆管理里录车时**车型是一个纯输入框** —— 不是下拉，也没有建议列表。
车队的车型列不全，硬塞进 9 个选项里只会逼着人选一个差不多的；
而挂 `datalist` 做建议时 Chrome 右侧会出现下拉箭头、看着还是像个下拉，
所以干脆去掉，就是一个干净的输入框：想写什么写什么（「依维柯」「9米6冷藏」都行）。
**车型不预填**：预填任何一个都会让没注意改的人悄悄录成那个车型
（原来预填 `CAR_TYPES[0]`，参数表一调整顺序就会变成皮卡）。

那油耗怎么算？基准表是**一条条油耗直线**，车型名进来后分三步找：

| 情况 | 处理 | 界面提示 |
| --- | --- | --- |
| `exact` 原样命中（如「皮卡」） | 用该档的直线 | 显示这条直线的参数 |
| `keyword` 关键词命中（「皮卡车」→皮卡、「9米6冷藏」→冷藏车、「半挂牵引」→牵引车） | 用对应档的直线 | 显示「识别为皮卡档」 |
| `generic` 认不出来（如「依维柯」） | 按通用中型货车估（空载 18 + 每吨 0.7） | **明确提示**「按通用中型货车估算」 |

关键词命中覆盖：皮卡 / 面包 / 冷藏冷链 / 自卸泥头渣土 / 牵引半挂集卡 / 平板栏板 / 轻卡 / 中卡 / 厢式。
认不出来时**绝不硬套牵引车**（那会让一辆小货车的标准油耗虚高近一倍），而是走通用档并如实告诉用户。

### 9 种基准档位

`src/data/vehicles.js` 的 `VEHICLE_TYPES`，加档位只改这张表：

| 档位 | 空载 L/100km | 每吨增量 | 额定载重 | 满载基准 | 油箱 |
| --- | --- | --- | --- | --- | --- |
| 皮卡 | 8.0 | 1.10 | 1.0 t | 9.1 | 80 L |
| 面包车 | 9.0 | 1.00 | 1.5 t | 10.5 | 70 L |
| 轻卡 | 12.0 | 0.90 | 4 t | 15.6 | 120 L |
| 厢式货车 | 15.5 | 0.85 | 8 t | 22.3 | 300 L |
| 中卡 | 17.0 | 0.75 | 10 t | 24.5 | 200 L |
| 冷藏车 | 17.5 | 0.90 | 12 t | 28.3 | 600 L |
| 平板车 | 20.0 | 0.55 | 25 t | 33.8 | 600 L |
| 自卸车 | 24.0 | 0.45 | 30 t | 37.5 | 400 L |
| 牵引车 | 26.0 | 0.28 | 32 t | 35.0 | 600 L |
| *通用（兜底）* | *18.0* | *0.70* | *10 t* | *25.0* | *300 L* |

```
百公里油耗 = 空载油耗(档位) + 每吨增量(档位) × 实际载重
```

**为什么是直线而不是一个固定值**：油耗里只有滚动阻力那部分正比于总质量，
空气阻力只跟车速和迎风面积有关、怠速与附件跟载重也无关。
所以是「截距 + 斜率」，而不是「按吨位分档」（分档会在边界上跳变：
载重 15.9 t 和 16.1 t 算出两个油耗）。

斜率差好几倍也是同一个道理：皮卡自重两吨上下，多装 1 吨是增重 50%；
牵引车自重九吨、满载四十吨，多装 1 吨只增重 2.5%。

车辆模块原来存的 `normFuel` 是「每车型一个固定值」，现在它是从基准表**派生的满载基准**
（`CAR_TYPE_NORM_FUEL`，自定义车型走通用档），车辆档案上那个值只作参考，
真正的考核基准每趟按实际载重算。

## 路线模块

一条路线 = **起点 + 终点 + 公里数 + 途经收费站**。

### 收费站价格是「车型 + 金额」的行

同一个收费站，皮卡和 30 吨自卸车不是一个价 —— 2020 年起全国货车高速按轴型收费，
所以每条路线的总过路费也是**分车型**算的：

```
某车型在这条路线上的总过路费 = Σ 各收费站该车型的价格
```

录入界面上每个收费站下面就是一串「车型 + 金额」的行，可以加行也可以删行：

```
苏州新区
  [牵引车 ▾]  [ 85 ] 元   ✕
  [皮卡  ▾]  [ 25 ] 元   ✕
  [自卸车 ▾]  [ 92 ] 元   ✕
  + 添加车型价格
```

**车型下拉取自车辆管理里实际录入的车型**（一辆车都没录时退回基准表并提示），
所以只给自己有的车填价，不用在一堆用不上的车型里划过去。
下拉还会并上这条路线里已经写过的车型 —— 否则删了某台车之后，
老路线里那个车型在下拉里没有对应项、会显示成空白。
同一个收费站里同一个车型填两次会被拦下（否则压成 map 时会悄悄合并）。

列表页每一行用胶囊列出各车型的总价，汇总卡给出一条区间（最低车型 ~ 最高车型）。

### 主键是「起点 + 终点」

和车牌号、手机号一样，导入与录入都按这个判重：同一条路线录两次会被拦下。

### 删路线会连带清掉趟次

路线上挂着趟次记录时，删路线前会提示「该路线上还有 N 条趟次记录，会一并删除」，
确认后一起清掉，不留孤儿记录。

## 趟次管理

这是「精细化运营」真正落地的地方。

### 趟次记录

| 字段 | 说明 |
| --- | --- |
| 运输日期 / 路线 | 必填；选路线会自动带出公里数 |
| 车型 | **不在表单里**：它绑定在车辆上，选完车辆自动带出（记录里存一份快照，以后车改了车型也不影响历史趟次） |
| 司机 | 必填；**考核对象** |
| 车辆 | **必填** —— 车型由它带出，没有车辆就没有车型，也算不出油耗指标 |
| 实际载重 | 必填；算每吨耗油要用 |
| 实际油耗 | 必填；这一趟实际加了多少油 |
| 油费单价 | 选填，元/L。**按趟记** —— 油价一直在变，用一个全局单价算不准成本。新增时会带出上次用过的价 |
| 过路费 | 按「路线 + 车型」自动带出，可改 |
| 运费收入 | 用于统计司机当月创收 |
| 已结算 | **勾选**，默认不勾（待结算）。运费很多不会当场结，默认「已结算」会把账算错 |

### 汇总条

只留四张：**趟次 / 总里程 / 实际油耗 / 油费合计**。
「每吨百公里耗油」「吨·百公里」在油耗对比的司机行里还能看到（那是分母），
但汇总条上不再重复；结算相关的数字全部挪到「收入」模块。

### 单趟算账

```
油费     = 实际油耗 × 油费单价
单趟成本 = 油费 + 过路费
单趟毛利 = 运费收入 − 单趟成本
```

录入弹窗里实时显示这四个数；趟次明细里每趟都有「油费 / 单价」「过路费 / 成本」「运费 / 毛利」三列，
毛利为负标红。汇总卡给出「油费合计」（附成本）与「待结算运费」（附已结金额与未收趟数）。

油费单价**没填时油费算 0**，不拿某个默认油价硬凑 —— `hasPrice` 区分「没填」和「填了 0」，
明细里显示「未填单价」而不是一个假数字。

### 结算状态

明细视图可按「全部 / 待结算 / 已结算」筛选，胶囊上带各自趟数。
「待结算运费」就是应收账款的提醒。

**注意钱是按全部趟次汇总的**：运费、油费、过路费跟拉了多少货没关系，
所以不像油耗指标那样排除空载趟次。

车型与公里数在录入时**快照**下来：路线以后改了公里数、车辆以后改了车型，历史趟次都不该被改写。

录入时下方会实时给出这一趟的油耗体检：标准油耗、实际油耗、折合百公里、
节油（或超耗）多少升、节油率百分之几。

### 核心指标：每吨每百公里耗油量

```
每吨每百公里耗油量 = 实际油耗 ÷ (载重 × 公里数 ÷ 100)     单位 L / 吨·百公里
```

**为什么用它而不是「百公里油耗」**：百公里油耗不区分拉了 30 吨还是 5 吨，
同样一条路，拉轻货的司机数字天然好看。按「吨·百公里」一除，载重就被归一化掉了 ——
于是同一条路线、同一类型车辆的司机可以直接横向比。

同一条路线（苏州→上海，108 km）、同车型（牵引车）：

| | 载重 | 实际油耗 | 百公里油耗 | **每吨百公里** |
| --- | --- | --- | --- | --- |
| 甲司机 | 30 t | 35.0 L | 32.41 | **1.080** |
| 乙司机 | 18 t | 33.0 L | 30.56 | **1.698** |

**按百公里油耗看，乙更省（30.56 < 32.41）—— 但乙拉的是轻货，他其实费油得多。**
按吨归一化之后甲明显更省。自检里专门钉了这条：断言「甲的绝对油耗更高」
且「甲在页面上排在乙前面」。

### 汇总口径：加权，不是算术平均

```
组内每吨百公里 = Σ油耗 ÷ Σ(载重 × 公里数 ÷ 100)
```

不是各趟指标的算术平均 —— 否则跑一趟 1 公里的短途会和 100 公里的长途等权。
另外每组的指标**不是**一个数字：每位司机同时给出单趟的**波动范围**（min ~ max），
用来回答「同一条路上这位司机大概烧多少」。

### 空载趟次不计入

载重为 0（空载返程）时除数为 0，算不出每吨耗油。这种情况**显示「—」并排除在对比之外**，
而不是拿 0 顶替 —— 否则一列空载返程会把平均值拉得好看得不真实。
汇总里会明确写出「跳过 N 趟」。

### 分组：路线 → 车型（或车辆）→ 司机

```
苏州 → 上海（108 km）· 6 趟 · 平均 1.389 L/吨·百公里
  └ 牵引车   2 位司机 · 6 趟 · 平均 1.389 · 波动 1.080 ~ 1.698
      ├ 1  甲司机   3 趟 · 324 km · 平均 30 吨      1.080   L/吨·百公里   范围 1.080 ~ 1.080
      └ 2  乙司机   3 趟 · 324 km · 平均 18 吨      1.698   L/吨·百公里   范围 1.698 ~ 1.698
```

中间那一层可以切换：

- **按车型分组** → 看「同一条路、同一类型车辆、不同司机」谁更省
- **按车辆分组** → 落实到具体某台车，看「同一条路、同一台车、同一司机」的稳定区间

趟次明细里也有一列「每吨百公里」，以及吨·百公里（Σ 的分母）。

### 已去掉的东西

按需求去掉了标准油耗、节油量、节油率、奖金那一整套（它们依赖「车型基准 + 载重」推一个理论值，
再用实际值去比）。现在只保留**实测口径**的每吨百公里耗油量，横向比的是司机之间的实际差异。
车型基准表仍然保留，但只用于两件事：新车录入时给一个满载参考油耗与油箱容量；
以及数据体检（判断某一趟的油耗是否低到物理上不可能）。

只关心钱：哪些运费还没收到、压在哪个月、谁跑的。运费在「趟次管理」里录入，这里只看结算。

四张卡：**待结算运费**（附未收趟数与平均每趟）、**已结算运费**、**运费合计**（附成本与毛利）、

2026-10   3 趟   待结算 ¥5,000（2 趟）   已结 ¥0        合计 ¥5,000

## 成本

五个来源汇总成一张饼图，可以按月回看。

| 来源 | 怎么来的 |
| --- | --- |
| **车辆折旧** | 车辆购置价格按 5 年直线法、残值 10% 计提 —— 但**按当月时点判断** |
| **员工成本** | 司机的月工资合计（司机管理里录入） |
| **油耗成本** | 趟次的 `实际油耗 × 油费单价` |
| **过路费** | 趟次的过路费，单独列一项不并进油耗 |
| **手工成本** | 手动录入，分车辆配件 / 车辆证件 / 其他 |

折旧与人工是「按月」的概念，油耗/过路费/手工是按日的流水，所以统一按月份看。

### 折旧不是「月折旧 × 车数」

这是最容易算错的地方。成本页用的是**时点计提**：

- 那个月**还没买**这辆车 → 不计提（不能把买车之前的折旧也算进去）
- 到那个月**已经提满 5 年** → 不再计提（账面停在残值）
- 刚好买到第 60 个月还在提，第 61 个月起停

所以同一批车在不同月份的折旧额是不一样的。自检里对这三种情况都有断言（含闰年 2 月的月末边界）。

### 图表

两张，都是**自绘**，没有引 echarts：

- **成本构成** —— 环形图（SVG `stroke-dasharray` 画弧），图例带金额和占比，
  鼠标划过会高亮对应扇区、其余变淡。中间显示当月合计。
- **按车辆** —— 分段堆叠的横向条形榜，一根条里同时看出这台车的
  折旧 / 油耗 / 过路费 / 配件 / 证件各占多少。条宽以**最大值**为基准而不是总和，
  这样小项之间的差异才看得清。超过 8 台折叠成「其他 N 台」。

### 手动添加成本

用途决定表单长什么样：

| 用途 | 表单 |
| --- | --- |
| 车辆配件 | 日期 + 金额 + **必须选一台车** + 备注 |
| 车辆证件 | 日期 + 金额 + **必须选一台车** + 备注 |
| 其他 | 日期 + 金额 + 备注（**不挂车**） |

两个细节：

- 切到「其他」时**会清掉已选的车辆**，并且 `toCostPayload` 也会再清一次 ——
  否则一个残留的 `vehicleId` 会让这笔钱悄悄算进某台车的成本里。汇总层也做了防御：
  即使库里真有这种脏数据，`其他` 也不会被归到任何车上。
- 删车时挂在它身上的成本会一起清掉，避免留下指向不存在车辆的孤儿记录。

### 总额与分项分开摆

总额（本月总成本）单独做成一条 hero，四个分项（折旧 / 人工 / 油耗 / 手工）在下面一行。

一开始五个卡都塞进 `grid--kpi`，而那个栅格在桌面端是 4 列 —— 第 5 张「手工成本」
就孤零零占一行，右边空一大片。而且总额跟分项本来也不是一个层级：
总额是结论，分项是拆解。现在 4 张分项卡正好铺满一行。

### 两个视图：总览 / 按车辆

车辆一多，塞在总览里的一条小榜根本看不过来（超过 8 台就折叠成「其他 N 台」，
数字还挤在一起）。所以按车辆独立成一个视图：

| 视图 | 内容 |
| --- | --- |
| **总览** | 总额 hero + 四张分项卡 + 成本构成饼图 + 成本最高的 6 台车 + 手工成本明细 |
| **按车辆** | 一张完整的逐车成本表 |

「按车辆」视图针对**车多**做了三件事：

- **可排序**：车牌 / 折旧 / 油耗 / 过路费 / 配件 / 证件 / 合计，点表头切换升降序
- **可搜索**：按车牌或车型过滤
- **可筛选**：默认「只看有成本的」，也可切到「全部车辆」

每行还画了一根**迷你堆叠条**（折旧 / 油耗 / 过路费 / 配件 / 证件各一段），
金额之外一眼看出这台车的钱主要花在哪。表尾有合计行，最后一列是占全队的百分比。

视图与月份都写在 hash 上，可以深链接：
`#/costs?view=vehicle&month=2026-10`。

### 自由选择月份（但不能选到未来）

成本页顶部是一个月份选择器：中间点开原生月份选择器，两边前后翻月，
另有「本月」快捷按钮；选到没有数据的月份会提示一句，不至于以为页面坏了。

**封顶到当月**，三层都堵住：

- 原生 `input[type=month]` 上挂 `:max="当月"`，选择器里根本点不到未来
- 到当月时 **next 箭头禁用**（变灰、`disabled`、`title` 说明「已经是最新的月份了」）
- `clampMonth()` 兜底：不管这个值从哪来（手改的 hash、旧书签），落在未来都拉回当月

为什么不让看未来：折旧不会提前计提、趟次和成本也都不允许填未来日期，
所以未来月份**永远是空的**——能选过去只会让人以为「数据丢了」。

收入页的月份选择器多一个「**全部**」并默认选中它 —— 收账时最关心「一共还差多少没收」，
比「本月欠多少」更常用。收入页的「按月份看」表每一行都可以点，直接跳到那个月。

两页的月份都写进 hash：`#/costs?month=2026-03`、`#/income?month=2026-10`，
可以各自收藏。
### 要真正落地还得注意

1. **里程要以路单 / GPS 为准**，加油量以油卡记录为准 —— 只奖励节油会诱导少报加油量
2. **季节与路况**：冬天、堵车油耗天然更高，跨季度直接比会冤枉人
3. **最好限制在同一辆车**：同车型不同车龄 / 车况，油耗能差 10%
4. **怠速油耗**：长时间怠速等装卸也会算进百公里油耗，严格说该拆成「行驶油耗」和「怠速油耗」

## 移动端适配

- **断点** 560 / 720 / 760 / 900 / 1120，移动优先
- **菜单** 桌面端（≥ 900px）左侧边栏，移动端（< 900px）底部标签栏，两套都由 `router.js` 的 `TABS` 驱动
- **两套列表 DOM**：`≥ 760px` 渲染真表格、`< 760px` 渲染卡片列表（`<dl>` 标签值对）
- **底部安全区**：内容区底部预留 `标签栏 + env(safe-area-inset-bottom) + 84px`；
  底部抽屉与确认框的按钮区同样带安全区 padding，不会被手势条压住
- **表单** 15px 字号（避免 iOS 聚焦自动缩放）、`inputmode` 唤起数字键盘、`type="date"` 唤起日期选择、`viewport-fit=cover`
- **无障碍** 完整尊重 `prefers-reduced-motion`；确认框支持 Esc 取消、Enter 确认

### 六个曾经踩过的坑（都已修，并写进了代码注释）

1. **绝不在 `body` 上写 `overflow-x: hidden`**。它会让 `body` 变成滚动容器，
   既裁掉右侧内容（表现就像「内容被切了」），又让所有 `position: sticky`（顶栏、表头）失效。
   改用 `overflow-x: clip`：同样不出现横向滚动，但不建立滚动容器，sticky 正常工作。
   卡片上同理 —— `.card--clip` 用的也是 `clip` 而不是 `hidden`。
2. **所有栅格 / flex 子项一律 `min-width: 0`**。CSS 里 flex/grid 子项的默认 `min-width: auto`
   会拒绝收缩到内容宽度以下，一张宽表格或一长串数字就能把整页顶出横向滚动条。
3. **SVG 的 presentation attribute（`fill="…"`）不支持 CSS 变量**，
   写了 `var(--x)` 会整条失效、退回默认黑色。图表内的文字颜色统一用 class 定义。
4. **`appearance: none` 会把日期输入框的原生日历图标一起干掉**。
   `.input` 上为了统一表单外观关掉了原生样式（`.select` 需要它来换成自绘箭头），
   结果 `input[type="date"]` 看起来就是个普通文本框、点不出日期选择器。
   现在对日期类型显式 `appearance: auto`，并在输入框上挂 `showPicker()`。
   这条有回归断言守着：既断言渲染出的 `type="date"` 与 `max`，
   也直接读 `app.css` 断言日期规则里有 `appearance: auto`。
5. **日期框光有 `type="date"` 还不够，得挂 `@click` 才会「点一下弹出来」**。
   原生只在**右侧那个小日历图标**上响应点击，点文本框区域只会聚焦到
   「年 / 月 / 日」里的某一段 —— 用户的感觉就是「点了没反应」。
   统一用 `utils/datePicker.js` 的 `openDatePicker`（内部调 `showPicker()`，
   并把「已打开 / 非用户手势」抛出的错吞掉）。
   这条吃过一次亏：车辆弹窗挂了、**司机弹窗的两个日期框和趟次的日期框都漏了**。
   现在有两条断言守着 —— 一条单测 `openDatePicker` 本身，
   一条**静态扫描所有组件模板**，任何 `type="date"` 的输入框没挂就会让自检失败。
   后来还发现 `isDateInput` 用的是 `el.type.startsWith('date')`，
   于是 `month` / `week` / `time` / `datetime-local` **全都不被识别** ——
   做月份选择器时又踩了一次同样的「点了没反应」。现在改成了白名单判断，
   静态扫描也扩到了整个日期时间家族。
6. **scoped 样式挡不住全局类名，重名会让整块 UI 糊掉**。
   `app.css` 里有一组**全局**的 `.bar`（归档仪表盘用的 6px 高进度条）。
   成本页的工具条和 `BarList` 的每一根条都用了 `class="bar"`，
   结果被套上 `height: 6px` + `overflow: hidden`：
   月份选择器和页签全部被裁成两个空框，条形榜的标签全叠在一条线上。
   `<style scoped>` 只给选择器加了个属性选择器，**并不会把全局规则隔离掉**。
   现在 `BarList` 统一用 `bl` / `bls` 前缀，成本页工具条用 `costbar`，
   并且有一条回归断言：把每个组件 scoped 样式里的类名与 `app.css` 的全局类名求交集，
   非白名单的重名一律失败（`.input` / `.field` / `.pill` 等 6 个「有意复用的基础类」在白名单里）。

### 数字输入框的滚轮防护

`type="number"` 的输入框一旦获得焦点，鼠标滚轮经过就会**直接改数值且没有任何提示** ——
往下滚页面时很容易把「载重 32」滚成「31」。现在装了全局防护（`utils/wheelGuard.js`）：
在捕获阶段把焦点交出去，浏览器随后处理滚轮默认行为时输入框已失焦，数值不会被改，页面照常滚动。
用全局监听而不是逐个加 `@wheel`，以后新增的输入框自动生效。这段逻辑有单元测试覆盖。

### 应用不内置任何数据

校验（`vehicleRules` / `driverRules` / `routeRules` / `tripRules`）、读表（`sheet.js`）、

以后直接换成接口调用即可，页面不用改。

## 技术选择说明

- **不引 SheetJS 之类读 Excel 的库**：`xlsx` 压缩后 300KB+，而且 npm 上的版本偏旧、有已知漏洞。
  `.xlsx` 本质是一个 ZIP 包加几个 XML，而浏览器与 Node 18+ 都自带 `DecompressionStream('deflate-raw')`，
  于是手写了一个「够用的」读取器：只读、只读第一张表，对本项目的导入场景完全够，产物体积为零。
- **不用图表库**：成本模块的饼图与条形榜是自绘 SVG/CSS（一个环不值 300KB 的依赖）（节油排行用的是文字表格而不是柱状图，因为要看具体数字）；已归档的报表模块当时也是自绘 SVG。
- **不用 vue-router**：六个模块 + 查询参数，20 行 hash 路由足够，还天然支持静态托管与任意子路径。
- **不用 Pinia**：两个档案用 `reactive` + 模块级导出即可，跨页共享、改一处全站同步。
- **产物**：`index.js` 274KB / gzip 89.9KB，`index.css` 70KB / gzip 11.7KB（含 Vue 3 运行时）。

**车型基准表与油耗模型**
- 9 种车型、每种都有油耗直线参数、载重区间覆盖额定载重
- 满载基准 = 空载 + 每吨增量 × 额定载重（逐个核对，不是抽样）
- 皮卡的每吨增量是牵引车的 3 倍以上；油耗随载重严格单调递增
- 不认识的车型退化成牵引车档（不会算出 NaN）；载重不填时按额定载重、载重 0 是真的空载
- 标准油耗、节油量、节油率、百公里对比、每吨公里油耗的数值逐项核对
- **核心断言**：甲的绝对油耗更高、但节油率也更高 —— 证明「只看绝对油耗会奖励错人」
- 汇总只统计填了实际油耗与里程的趟次；奖金公式与「超耗不倒扣」；物理下限异常检测
- 门槛常量（≥3 趟、≥3%）

**路线与趟次**
- 路线标识归一化、分车型过路费汇总、价格区间、空路线不炸
- 起终点相同 / 公里数 0 / 非数字 / 超大 / 缺起点 / 重复路线（含「编辑自己时不算重复」）都被拦下
- 收费站没名字 / 同路线重名 / 价格为负 / 价格非数字被拦下；没填任何价格只给软提示
- payload 转换：地名去空格、公里数保留一位小数、空值与 0 都不写入价格、整条空的收费站被丢掉
- 趟次：缺路线 / 缺司机 / 缺车型 / 车型越界 / 油耗 0 / 载重为负 / 载重超 100 吨 / 缺公里数 /
  未来日期 / 运费为负被拦下；油耗高得离谱与低于物理下限都只给**软提示**（不阻塞提交）
- 趟次去重键「日期+路线+司机+车」

**油耗指标（每吨每百公里）**
- 指标算法逐项核对：30 吨跑 108 km 烧 35 L → 1.080；载重翻倍指标减半
- **空载返回 null 而不是 0**（除数为 0 时不能拿 0 顶替，否则会拉低平均值）
- **核心断言**：甲拉 30 吨烧 35 L、乙拉 18 吨烧 33 L —— 甲的绝对油耗更高，
  但每吨百公里更省，断言排行里甲在前。这条就是整个指标存在的理由
- 汇总用**加权口径**（Σ油耗 ÷ Σ吨·百公里）而不是算术平均，并用一组极端数据验证两者明显不同
- 单趟波动范围（min / max）；只有一趟时上下限相同
- 空载 / 没里程 / 没油耗的趟次被排除，`skipped` 计数正确
- 页面渲染：路线与车型分组、司机行、「每吨每百公里耗油量」「范围」「波动」都出现；
  并断言**标准油耗 / 节油率 / 奖金 / 油价这几个词已经完全从页面消失**

**月份不能选到未来（回归）**
- `currentMonth` / `isFutureMonth` / `clampMonth` 三个纯函数逐个核对（含跨年、'all'、空值）
- 当月时 next 箭头 `disabled`、`aria-label` 变成禁用提示；过去月份则可用
- `input[type=month]` 的 `max` 等于当月
- 收入页选「全部」时前后翻月整条隐藏（没有「哪个月」可言）
- 月份被钳制：`#/costs?month=2099-01` 会落回当月
- 没有趟次的月份不再显示「平均每趟」（原来会拿 1 当除数，算出个假数字）

**月份选择（回归）**
- `isDateInput` 认得 month / week / time / datetime-local —— 原先用 `startsWith('date')` 判断，
  这四个全被漏掉，表现就是月份框「点了没反应」
- 静态扫描从只查 `type="date"` 扩到整个日期时间家族，新增月份框忘挂处理函数会直接失败
- 月份走 hash：`#/costs?month=2026-03`、`#/income?month=2026-10` 能筛出对应月份
- 成本页两个视图走 hash：`#/costs?view=vehicle` 直接进逐车表，且此时不再渲染饼图
- 逐车表：7 个可排序表头、表尾合计行、占比、行内迷你堆叠条、搜索框、有/无成本筛选
- 收入页选「全部」时显示可点击的月份导航表，选中单月后收起

**成本**
- 折旧时点计提：当月还没买 → 0、提满 5 年 → 0、第 60 个月仍在提、第 61 个月停
- 月末边界：2026-02 = 28 号、2024-02 = 29 号（闰年）、2026-12 = 31 号
- 五个来源逐项核对：折旧 / 人工 / 油耗 / 过路费 / 手工，以及总额
- 逐车归集：某车的配件、证件、油耗、过路费、折旧分别对不对
- **「其他」不会被算进任何车** —— 即使库里那条记录带着车辆 id
- 切用途清车辆：改成「其他」后 `vehicleId` 被清空
- 饼图只收 >0 的项、按金额倒序、占比之和为 1、空数据返回空数组
- 页面渲染：五张卡、环形图是 SVG `<circle>` + `stroke-dasharray`、图例带百分比、
  按车辆是分段堆叠、三笔明细与用途标签、说明里点出折旧口径与油价缺失的影响
- 表单：没选用途时不出现车辆选择；配件/证件的编辑态要求选车；「其他」不出现车辆选择

**收入 · 运费结算**
- 一键标记：`setTripSettled` 生效、重复标记不重复计数、批量撤销返回真实改动条数
- 汇总：待结算 ¥5,000 / 已结算 ¥1,500 / 结算进度，逐项核对
- 按月份分区：`2026-10` 与 `2026-09` 各自独立成行
- 页面有「标记已结算」按钮；空库与「全部已结算」两种空状态文案不同（不再一律说「账都收齐了」）
- 断言收入页上**不出现**油耗指标（每吨百公里），它是纯钱的视图

**油费单价与结算状态**
- 油费单价选填；非数字 / 为负 / 超 200 元/L 被拦；正常油价通过
- `油费 = 油耗 × 单价`、`成本 = 油费 + 过路费`、`毛利 = 运费 − 成本` 逐项核对；跑亏为负
- **没填单价时油费算 0**，`hasPrice` 区分「没填」与「填了 0」
- 结算：不勾是待结算、勾了是已结算、非 `true` 的值一律当待结算
- 页面渲染：油费单价与结算字段存在、默认待结算、结算是 checkbox 语义、
  汇总卡有「油费合计」与「待结算运费」

**身份类字段不做格式限制（回归）**
- 车牌：`B-MW 1234` / `CA 12345` / `1-AB-234` / `ÜN-XY 99` 等写法全部放行；归一化**不会**插分隔符或剥掉 `-` `.`
- 手机号：`+49 30 1234567` / `(020) 7946 0958` / `12345` 全部放行；横线与括号原样保留
- 姓名：单字名、带数字、`O'Brien`、`Jean-Luc Picard`、80 字长名全部放行
- 驾驶证号：`AB-1` / `DE 1234/5678` / `my-license` 全部放行
- 但结构性的两条留着：**必填**与**唯一性**（车牌与手机号是导入主键，靠它判新增/替换）
- 这两个正则（`PLATE_RE` / `PHONE_RE`）仍然导出但**没有启用**，以后想开格式提醒随手可用

**司机工资**
- 选填（不填通过）；`8,800 元` / `¥12000` 能清成数字；`八千` 清成 0
- 非数字 / 为负 / 超上限被拦下；填 0 只给软提示
- 在可上传字段里（导入模板含工资列）、能带进 payload、编辑态能回填
- 车辆列表**按车型分组**：分组开关、组头（台数 / 合计载重 / 月折旧）、车型数量都断言

**车型自由输入（319 项里的独立一段）**
- 原样命中 / 关键词命中 / 通用兜底三种情况逐个核对（皮卡车→皮卡、9米6冷藏→冷藏车、半挂牵引→牵引车、重型自卸→自卸车）
- `isKnownType` 只认原样存在的、`isEstimatedType` 只认通用档
- 未知车型**可以通过校验**但带一条油耗基准软提示；已知车型没有这条提示
- 车型仍必填、车型名过长被拦、未知车型按通用载重区间给提示
- 认不出来的车型用通用货车估，**不是**硬套牵引车
- **回归**：收费站价格按实际写进来的车型名存，不拿基准表过滤（自定义车型的价格不会被悄悄丢掉）
  —— 这条抓出过一个真 bug：store 与 rules 里三处都在按 `CAR_TYPES` 遍历，会把自定义车型的价格丢掉

**路线管理页 / 油耗考核页（SSR）**
- **校验规则清单（回归守卫）**：把 5 个表单里每条规则的「代表性非法输入」都跑一遍，
  少一条就点名报出来。这类丢失的症状很隐蔽 —— 功能看着还在，就是不拦了；
  曾经真的丢过 4 条（车牌长度 / 车牌格式 / 手机号格式 / 载重上限），
  而且是在一次毫不相关的改动里丢的，所以现在有一份清单钉着，丢了会直接点名
- **日期输入框**：`openDatePicker` 的行为单测（认得 date / 不认 text / 不支持 showPicker 不报错 /
  已打开抛错被吞 / 传空不炸），外加**静态扫描所有组件模板**，任何 `type="date"` 没挂 `@click` 即判失败
- 趟次表单**没有车型下拉**（车型随车辆带出）；车辆是必选、没有「不指定」；提示写明车型自动带出
- 车辆表单的车型是**纯输入框**：没有 `select`、没有 `datalist`、输入框没有 `list` 属性、不预填值，但仍会提示油耗基准怎么算
- 路线 / 趟次的车型下拉**取自车辆管理里实际录入的车型**，不会把基准表里的车型全列出来；
  车队为空时退回基准表并提示；下拉会并上记录里已有的车型（删车后老数据仍可读）
- 路线页：空状态、菜单四项齐备、搜索提示、按车型列出各车型总过路费（牵引车 ¥145 / 皮卡 ¥43 分别核对）
- 路线表单：新增与编辑两态、带出已有收费站、9 个车型价格输入、每站已填车型数、额定吨位标注
- 路线 CRUD：编号自动分配、主键判重（含带空格）、编辑生效、删除
- **节油排行**：给两位司机灌入「重货 vs 轻货」两组数据，断言页面上**甲排在乙前面**
  —— 这是整个模块的核心口径，用渲染结果钉住
- 趟次表单：联动字段齐全、车辆选填、同车型才可比的提示、过路费自动带出说明
- 趟次明细：表格与卡片两套 DOM、实际/标准/百公里/节油率列齐全
- 删路线连带清趟次（`removeTripsByRoute` 返回值与剩余条数都核对）

## 已知边界

这是**演示项目**，不是生产系统：

- 六个模块的数据都存在浏览器 `sessionStorage`：刷新不丢，但**关掉标签页就没了**，也换不了设备
- 没有登录、权限、多租户
- 唯一性、格式校验都只在前端做，没有服务端兜底
- **油耗考核只认自己录进去的数据**：里程靠手填，没有接 GPS / 路单，加油量也没有接油卡，
  所以防作弊只能到「交叉校验 + 物理下限提示」这一层
- 排行没有做季节 / 天气 / 路况修正，跨季度直接比会冤枉人
- 奖金只按「节油金额 × 30%」一种口径，没有排名奖金池、没有月度封顶
- 路线的公里数是单程固定值，没有往返区分、没有备用路线、没有实时路况绕行
- 收费站价格按车型存，没有按轴型分类、没有桥隧单独加价、没有分时段费率
- 事故/违章记录没有附件（现场照片、责任认定书），只有文字描述与金额
- 车辆与司机之间还没有关联关系
- 折旧口径写死 5 年 / 残值 10% / 直线法，不处理加速折旧，也不处理年中购入的半年惯例
- 只读第一张工作表；不支持 `.xls`；不解析合并单元格
- 车辆与司机的导入面板「预览确认」那一步没有自动化渲染测试（数据管线有完整断言，UI 靠手点）
- **自定义车型的油耗基准是估算的**：认得出关键词就落在对应档位，认不出来一律按通用中型货车估，
  所以「依维柯」和「9米6冷藏」的标准油耗精度不一样；要精确就得往基准表里加档位
- 删除只按条进行，没有批量操作
